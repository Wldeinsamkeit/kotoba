# 日语单词记忆方法流程图

用途：快速参考记忆方法编写流程、决策树和质量校验。详细规则见 `日语所有单词记忆方法规则.md`。

---

## 📋 核心工作流程

```
┌─────────────────────────────────────────────────────────────┐
│  用户说「开始编写」/「开始第 X 组」→ 本批流程启动              │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  1. 读取规则文件                                             │
│     data/skill/日语所有单词记忆方法规则.md                    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  2. 读取当前批次文件                                         │
│     data/memory_methods/nx/batch_XX_methods.json             │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  2.1 词表/OCR 字段自检（每批先验货，避免围绕错词硬编）       │
│     检查 word / reading / meaning / sourceRaw 是否互相匹配   │
│     - 读音明显对不上：先回查来源或标为异常                  │
│     - 假名词但意思像汉字词：怀疑 OCR 漏字或截断              │
│     - 中文意思残缺/乱码：先修正或汇报，不编故事             │
│     示例：もん/せん/专业 → 应优先核对是否为 専門(せんもん)  │
│     示例：中/なかなか/々颇，很 → 应核对是否为 中々          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  2.5 更新「写作范围」关系图（默认 AI 自动跑，每新批必做）    │
│     先告诉用户：脚本正在跑 memory:writing-scope …            │
│     再执行：npm run memory:writing-scope -- --level n4        │
│             --batch 15                                        │
│     跑完简报：已编写词数 / 本批保留关系数                    │
│     ① 允许级别索引（N4→n5+n4）② 去掉未编写 target           │
│     ③ 读 writing_scope/{级}_batch_{NN}_writing_relations    │
│     用户说「脚本我跑过了」→ 跳过执行，只读现有文件           │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  3. 按规则编写全部单词（内部双线，对外一条）                   │
│     关系图只是素材，不是谐音的替代品。每词必须先过读音线：     │
│     A. 整体谐音候选  B. 拆分谐音候选  C. 固定读音/假名块候选  │
│     再过关系线：同音/同字/读音前缀/假名变化/词形派生/同场景词│
│     最后把 A/B/C 中最自然的一条与关系线融合成一条记忆法。      │
│     - 禁止只浏览关系后输出纯关系故事                         │
│     - 禁止用“有关系词”代替“发音怎么记”                       │
│     - 同字/固定读音关系只能辅助，不能单独冒充记忆法          │
│     - 若确实无自然谐音，必须写明改用固定读音/字形/外来语原因  │
│     - 故事生活化 + 固定读音补强                              │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  3.1 谐音候选硬门槛（每词必做，不因关系索引而跳过）          │
│     ① 先试整体谐音：读 2～3 遍，找最贴近中文声音            │
│     ② 整体不自然 → 拆成 2～3 段谐音                         │
│     ③ 仍不自然 → 找假名块/固定读音/罗马音/外来语            │
│     ④ 最后才决定不用谐音，并在心里给出“不用原因”           │
│     内部必须至少留下：整体候选/拆分候选/不用原因 三选二      │
│     输出审阅稿时：有自然谐音必须写进主链；无谐音才用替代法。 │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  3.5 同音不同字检测（每词必做）                              │
│     - 对照规则文档"同音不同字对照表"                         │
│     - 检测该词读音的罗马音归一值是否与已学词同音             │
│     - 搜索/关系查找同时支持汉字、假名、罗马音                │
│     - 若关系词已编写，必须查该词 JSON 的 reviewTip 后再融合  │
│     - 若有同音词：                                           │
│       a) 探讨能否辅助记忆 → 展示时加「🔗 同音：…」          │
│       b) 若同音词义差异大 → 展示时加 ⚠️ 对比提醒              │
│       c) 用户说「可以覆盖」→ 同音联想默认写入 JSON            │
│          （用户说「这个同音不覆盖」→ 该条同音不写 JSON）      │
│     - 新发现的同音对 → 更新规则文档对照表                    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  4. 逐词质量校验（五道关卡）                                 │
│     ✓ 词表/OCR 可靠性                                      │
│     ✓ 读音钩子真实性                                       │
│     ✓ 关系索引有用性                                       │
│     ✓ 故事一致性                                           │
│     ✓ 三秒回想测试                                         │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  5. 展示给用户审核（融合稿，不分两版，不含例句）             │
│     格式：序号. 词语（意思，读音）：记忆法 - 单词意思        │
│     主段已含谐音+关系对比；勿并列「谐音版/索引版」           │
│     主记忆法后复查关系边：同音/同字/前缀/浊点/相似假名等    │
│     有助记忆但未进主故事的关系，必须用「关联：」精简列出    │
│     例：预约 要列 予定；厚い 要串 暑い/熱い/厚い             │
│     可选简注：索引：…（仅审阅，禁止写入 JSON）               │
│     同音/易混另起：🔗 …  或  ⚠️ …                           │
│     审阅阶段不展示 exampleSentences（覆盖写入时再补）        │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  6. 用户给出批改意见                                         │
│     1、格式：e1、修改内容...  d2、删除... 
      2、根据用户提供的编号，不满意的返工修改。
      3、返工修改时能谐音的换谐音方法，谐音不够通顺的换其他记忆法。
      如同发音不同字的一起记忆，或者根据相近平假名字型的对比记忆
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  7. 按批改修订 → 展示【完整 40 词】给用户审阅                 │
│     - 审阅阶段禁止修改正式 batch_*_methods.json              │
│     - 每次用户提修改后，必须列出 1～40 全部词条（不可只发改过的）│
│     - 每条一条融合记忆法；不展示例句                         │
│     - 未点名的词保留 AI 本轮最终版，一并展示                 │
│     - ⚠️ 此阶段不写入 JSON，等用户明确确认                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  7.5 用户确认「可以覆盖/确认/写入」                          │
│     - 仅收到确认后才写入 batch_XX_methods.json               │
│     - 写入 40/40 全量覆盖（含 exampleSentences；审阅未展示） │
│     - 同音联想默认一并写入 JSON（用户说「同音不覆盖」除外）│
│     - 验证无默认占位场景 → 汇报「40/40 条，无遗漏」          │
│     - 若用户继续提修改 → 回到步骤 7，仍不写入                │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  8. 学习新规律，更新规则文件                                 │
│     - 新谐音/固定读音 → 添加到示例区                        │
│     - 新规则 → 添加到对应章节                               │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    完成，准备下一组                          │
│     用户再说「开始编写」下一批 → 回到步骤 2.5（AI 自动跑脚本）│
│     审阅下一批仍：不展示例句、不改 JSON，直到「可以覆盖」    │
└─────────────────────────────────────────────────────────────┘
```

## ✅ 质量校验清单

每个单词必须通过以下五道关卡：

```
┌─────────────────────────────────────────────────────────────┐
│                    关卡 1：词表/OCR 可靠性                   │
├─────────────────────────────────────────────────────────────┤
│  ✓ word / reading / meaning 没有明显错位                   │
│  ✓ 假名词、截断词、乱码义项已经回查或标注                  │
│  ✓ 没有围绕错误读音、错误汉字、错误意思编故事              │
│                                                             │
│  ❌ 不过关 → 先修词表或汇报异常，不进入编写                │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    关卡 2：读音钩子真实性                    │
├─────────────────────────────────────────────────────────────┤
│  ✓ 每词已先尝试整体谐音、拆分谐音、固定读音/假名块          │
│  ✓ 谐音候选已写出假名块/罗马音，并逐拍对照原词发音          │
│  ✓ 谐音基本符合原词发音                                    │
│  ✓ 能在真实生活里说出来                                    │
│  ✓ 不为了故事牺牲发音准确性                                │
│  ✓ 有关系索引时，也没有跳过读音线                          │
│                                                             │
│  ❌ 不过关 → 换谐音、改拆分，或明确改用非谐音法            │
│     不能把意译型联想包装成谐音                              │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    关卡 3：关系索引有用性                    │
├─────────────────────────────────────────────────────────────┤
│  ✓ 同音、读音前缀、假名变化优先转成记忆故事                │
│  ✓ 同字不同音/固定读音只作为补强，不单独当最终记忆法       │
│  ✓ 只选 1～2 条最高价值关系，不堆列表                      │
│  ✓ 未进主故事但有助记忆的关系，已在「关联」行交代          │
│                                                             │
│  ❌ 不过关 → 降权关系索引，回到读音线重写                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    关卡 4：故事一致性                        │
├─────────────────────────────────────────────────────────────┤
│  ✓ 故事由谐音延伸                                          │
│  ✓ 逻辑符合日常实际                                        │
│  ✓ 有具体人物、场景、动作、物品或情绪                      │
│  ✓ 有生活冲突或处境压力，最后能落到情绪/后果/意思          │
│                                                             │
│  ❌ 不过关 → 补冲突、补情绪、补后果；不要只做词典解释      │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    关卡 5：三秒回想测试                      │
├─────────────────────────────────────────────────────────────┤
│  ✓ 读者能感到：搞笑/惊讶/尴尬/生气/无奈/温暖              │
│  ✓ 故事有完整小戏（不能只有谐音一句）                      │
│  ✓ 看见 A 单词，3 秒内能想起 C 画面，再想起 B 意思          │
│  ✓ 不是“数学=数+学=数学”这类词典解释                      │
│                                                             │
│  ❌ 不过关 → 加强声音钩子、具体动作和结果                  │
└─────────────────────────────────────────────────────────────┘
```

## 🔧 常见问题处理

```
┌─────────────────────────────────────────────────────────────┐
│  问题：谐音太生硬/不自然                                    │
├─────────────────────────────────────────────────────────────┤
│  解决方案：                                                  │
│  1. 多试几个整体谐音，选最贴近的                            │
│  2. 拆成2-3段分别谐音，再合成故事                          │
│  3. 仍不自然 → 先查已编写关系词：同音/读音前缀/同字不同音  │
│  4. 关系也无法成故事 → 再改固定读音/字形联想/外来语        │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  问题：故事不符合生活逻辑                                    │
├─────────────────────────────────────────────────────────────┤
│  解决方案：                                                  │
│  1. 检查是否胡编乱造                                        │
│  2. 故事要贴近日常：家庭、学校、工作、食物、钱             │
│  3. 用户给的故事通常更生活化，优先保留原味                  │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  问题：不知道用什么方法                                      │
├─────────────────────────────────────────────────────────────┤
│  优先级顺序：                                                │
│  1. 用户提供的谐音/故事（最高优先级）                       │
│  2. 自然中文谐音 + 生活化故事                              │
│  3. 拆分谐音（2～3段）+ 生活化故事                         │
│  4. 固定读音/假名块 + 简短谐音或字形钩子                  │
│  5. 已编写同音不同字：能串故事就串，不能串就做对比提醒    │
│  6. 读音前缀：短词是长词开头词块时，优先拆出来做故事      │
│  7. 假名变化：长短音/浊点/一字差/词尾差                    │
│  8. 汉字透明时查同字不同音，能联系就做家族故事             │
│  9. 罗马音/英语/外来语相似                                  │
│  10. 最后才用纯汉字直觉/字形联想；不能一上来跳过谐音线    │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  问题：检索到关系后，写成词典解释/固定读音说明              │
├─────────────────────────────────────────────────────────────┤
│  解决方案：                                                  │
│  1. 先问：这个词有没有声音钩子？没有就写不用原因            │
│  2. 同字关系只负责补强读音，不负责单独完成记忆              │
│  3. 若关系词已学过，先读取其 reviewTip，贴出旧记忆链        │
│  4. 再判断新旧两词能否合并成同一个故事或对比                │
│  5. 若句子像“数学=数+学=数学”，判定失败，重写              │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  问题：词表字段疑似错误，AI 却继续编了                      │
├─────────────────────────────────────────────────────────────┤
│  解决方案：                                                  │
│  1. 先核对 word / reading / meaning 是否能互相解释          │
│  2. 发现 OCR 漏字、截断、乱码义项时，先列异常               │
│  3. 能从源文件安全修正就修正；不能确定就问用户              │
│  4. 禁止围绕错误字段生成“看似合理”的记忆法                 │
└─────────────────────────────────────────────────────────────┘
```

## ⚠️ 常见错误警示

```
┌─────────────────────────────────────────────────────────────┐
│  ❌ 错误：谐音发音偏差太大                                  │
│  例：すみ→扫地（发音不符）                                  │
│  ✓ 正确：すみ→私密（发音贴合）                             │
│  例：ふつう→服从、ひらく→一拉开，属于意译型伪谐音          │
│  ✓ 正确：先写 futsuu / hiraku，再找贴近音节的钩子           │
├─────────────────────────────────────────────────────────────┤
│  ❌ 错误：故事不符合生活逻辑                                │
│  例：木卡子开门（不自然）                                   │
│  ✓ 正确：木匣子藏老照片（贴近日常）                        │
├─────────────────────────────────────────────────────────────┤
│  ❌ 错误：只有谐音没有故事                                  │
│  例：谐音"XX"就结束了                                       │
│  ✓ 正确：谐音+1-3句具体小戏（有人物/动作/后果）            │
├─────────────────────────────────────────────────────────────┤
│  ❌ 错误：硬凑谐音                                          │
│  例：每个词都要谐音                                         │
│  ✓ 正确：汉字透明/外来语明显/固定读音稳定的词不必硬凑      │
└─────────────────────────────────────────────────────────────┘
```
