# 日语所有单词记忆方法规则

用途：给 `data/memory_methods/{级别}/batch_*_methods.json` 批量编写或修改日语单词记忆方法时使用。级别目录：`n5/`、`n4/`、`n3/` 等。这是本 app / 平台的核心记忆方法文件，不只服务 N5，也服务后续所有级别、所有批次的单词记忆生成。

核心原则：这个文件要像滚雪球一样持续变大。每一组用户修改并确认过的单词，都必须被认真复盘，提炼出可复用的记忆规律，再更新回本文件。以后生成新批次时，优先读取并遵守本文件。

参考风格：优先模仿已经确认过的前六批文件，并持续吸收后续批次中用户确认/修改过的表达：

- `data/memory_methods/n5/batch_01_methods.json` 到 `data/memory_methods/n5/batch_17_methods.json`
- `data/memory_methods/n4/batch_01_methods.json` 到 `data/memory_methods/n4/batch_30_methods.json`
- `data/memory_methods/n3/batch_01_methods.json` 到 `data/memory_methods/n3/batch_53_methods.json`

如果用户给出修改标记，同时遵守 `data/skill/修改规则.md`。

## 滚雪球更新机制

每一组单词被用户修改后，必须做这几步：

1. 回看本组被修改的词条，识别用户真正想保留的规律，而不是只机械替换某一句话。
2. 检索已确认批次和本规则，判断这是旧规律复用，还是新规律升级。
3. 把新规律沉淀进本文件，优先写成可执行规则、典型示例、固定读音或易混对比。
4. 再更新对应 `batch_*_methods.json` 和草稿文件，保持规则与数据同步。
5. 给下一组词时，先用本规则生成，不要回到通用、平庸、生硬的记忆法。

需要重点沉淀的内容：

- 用户亲自给出的谐音、拆分、故事和吐槽式表达。
- 单词之间的相似点、差异点、少一点/多一点、长音/促音变化。
- 常见汉字固定读音、浊化、特殊读法。
- 能跨批次复用的故事模板，比如生活场景、学习场景、家庭对话、食物、打工、考试、出门、迷路。
- 用户纠正过的错误方向，避免后续重复生成。

质量反思要求：

- 新批次如果生成质量不高，必须回看用户批改，找出低质量原因：是否硬凑谐音、是否没有用固定读音、是否没有把相似词放一起、是否故事不贴近日常。
- 谐音必须先校准发音，不能只看中文意思就硬凑。比如 `へん` 不能谐音成发音明显偏差的“边”，应优先找更贴近发音的“恨/很/哼”等；如果候选谐音不自然，就拆假名或换字形、联想、固定读音法。
- 有固定读音、透明汉字、外来语来源时，先用稳定知识打底，再加谐音故事；不要为了搞笑牺牲准确性。
- 外来语必须核对来源和意思，不能混淆相近英语。比如 `デパート` 来自 `department store`，是百货商店；公寓是 `アパート`，不要混成 `デパート`。
- 用户给出的故事通常更贴近日常，要优先保留原味；自己生成时要主动模仿这种“生活经验 + 俏皮谐音 + 明确含义”的结构。

## 文件结构要求

批次来源优先级：

- 编写或审核记忆方法时，优先以 `data/memory_methods/{级别}/batch_*_methods.json` 的词表为准。
- N5 正式批次放在 `data/memory_methods/n5/`，汇总文件为 `all_n5_memory_methods.json`。
- N4 词汇初版来自 `资源汇总/N4/MOJi辞書 - 红宝书N4N5 1~1000.pdf` 和 `资源汇总/N4/MOJi辞書 - 红宝书N4N5 1001~1220.pdf`，生成脚本是 `scripts/build_n4_memory_methods.cjs`，正式批次放在 `data/memory_methods/n4/`，汇总文件为 `all_n4_memory_methods.json`。
- N3 正式批次放在 `data/memory_methods/n3/`，生成脚本是 `scripts/build_n3_memory_methods.cjs`，汇总文件为 `all_n3_memory_methods.json`。
- 前端统一通过 `src/data/memoryMethods.ts` 静态 import 上述汇总 JSON，不再从 `public/` fetch。
- 如果 `data/batches/batch_*.json` 和 `data/memory_methods/{级别}/batch_*_methods.json` 不一致，先明确指出差异；除非用户指定，否则继续以 `data/memory_methods` 为准。
- 不要因为同编号 `data/batches` 里有重复旧批次，就把已经完成的词组重新生成一遍。

保持原有 JSON 字段，不随意改名：

- `word`
- `reading`
- `meaning`
- `elements`
- `mergedScene`
- `sceneScore`
- `reviewTip`
- `difficultyStars`
- `exampleSentences`

不删词，不换顺序。未确认前，新批次先放到 `data/memory_methods/drafts/` 作为草稿。

## AI 编写单词记忆方法的标准链路

任何 AI 在编写、审核或修改单词记忆方法时，必须先按下面顺序执行；不要跳过关系检索直接硬编故事。

1. 读本规则文件：`data/skill/日语所有单词记忆方法规则.md`。
2. 读目标批次或目标词表：
   - 正式批次优先读 `data/memory_methods/{级别}/batch_*_methods.json`。
   - 只有还没有正式记忆法批次时，才读词表源文件，例如 `data/word_relations/sources/n2_vocab.json`。
3. 词表/OCR 与字段一致性自检：
   - 每批正式编写前，先抽查并核对 `word`、`reading`、`meaning`、`sourceRaw`（如有）是否能互相解释。
   - 发现读音和汉字明显不匹配、中文义项残缺、乱码、只剩半个词、假名词却像漏了汉字时，必须先标为「词表异常」，不要围绕错误字段硬编记忆法。
   - 能从源 PDF、原始词表或同批上下文安全修正的，先修正；不能确定的，在审阅稿前列出异常并询问用户。
   - 典型警报：`もん / せん / 专业` 很可能不是要编「もん」，而是要核对 `専門（せんもん）`；`中 / なかなか / 々颇，很` 要核对是否为 `中々（なかなか）`；`妻 / つま / 子` 要核对中文意思是否误截。
   - 通过自检后才进入关系索引和记忆法编写。
4. 查单词关系（**先更新写作范围，再读过滤后的关系图**，见下节「关系编写范围」）：
   - 由目标批次确定 `writingLevel` 与 `writingBatch`（例：编写 `n4/batch_15` → N4 第 15 批）。
   - **默认：用户说「开始编写」（或同义：开始第 X 组、开始 batch_XX）时，由 AI 自动运行**（不必等用户手动敲命令）：
     ```bash
     npm run memory:writing-scope -- --level n4 --batch 15
     ```
     运行前须先告知用户：**「脚本正在跑：`memory:writing-scope`（n4 / batch 15）」**；结束后简短汇报结果（已编写词数量、本批保留关系数等），再开始列 40 条记忆法。
   - 若用户明确说「我自己跑过了 / 不要跑脚本」，则跳过执行，直接读已有 `writing_scope` 文件（并确认 `generatedAt` 对应当前批）。
   - AI 编写时**优先读**生成物：`data/word_relations/writing_scope/{级别}_batch_{NN}_writing_relations.json`（已去掉「尚未编写记忆法」的 target）。
   - 需要核对锚点全集时，读同目录 `{级别}_through_batch_{M}_written_keys.json`（M = 当前批号 − 1）。
   - 不要直接拿全量 `{级别}_word_relation_index.json` 里所有边编故事——其中很多 target 词在后续批次，学习者还没学过。
   - 若过滤后无边，再用谐音、字形、本批互链；**下一批**用户再说「开始编写」时，AI 同样自动跑 `memory:writing-scope`（批号为下一批）。
5. 写记忆法草稿（审阅阶段）：
   - **审阅阶段禁止修改正式 `batch_*_methods.json`**：在用户明确说「可以覆盖」「确认」「写入」之前，不得写入、覆盖或批量改动 `data/memory_methods/{级别}/batch_*_methods.json`；只在对话中展示完整 40 条融合记忆法供批改。
   - **审阅阶段不向用户展示 `exampleSentences`（例句）**：例句在确认覆盖写入 JSON 时一并补齐即可；对话里只展示记忆法正文（含可选 `🔗` / `⚠️` / 索引简注）。
   - **审阅用的「索引：…」行禁止写入 JSON**：对话里用于追溯关系图的 `索引：单词::读音 → …`、`edgeId`、簇锚说明等，**不得**原样放进 `mergedScene` / `reviewTip` / `elements`；覆盖时只写已编进故事的记忆法正文，关系信息最多用 `🔗` 串已学词。
   - 未经用户确认的新批次如需落盘，只能写到 `data/memory_methods/drafts/`，且不得用草稿覆盖正式批次。
   - 草稿与正式批次均须保留目标词原顺序和原 JSON 字段。
   - 每个词在落笔前必须**同时考虑**谐音/固定读音/字形 与 关系索引两条线（见下文「融合记忆法」）；向用户展示时**只给一条融合后的记忆法**，不再分「谐音版」「索引版」两栏。
   - 生成内容要体现“关系检索结果如何影响记忆法”，不能只写孤立谐音，也不能查到索引后只停留在说明关系。
6. 用户批改后，再更新正式记忆方法和规则文档：
   - 用户只要改了一个词，也要复盘其中的新规律。
   - 用户确认“可以覆盖/确认/写入”后，才按本文件的覆盖规则更新正式 `batch_*_methods.json`。
   - 新规律要同步沉淀到本规则文件，让下一批继续滚雪球。

### 关系编写范围（必遵守）

编写记忆法时，关系图分两步：**先定查询哪些级别的全量关系索引，再删掉学习者还没编写过记忆法的 target 词**。避免把 N4 词表后面批次、或更高级别词拉进当前批故事，增加记忆负担。

#### 1）允许查询的关系索引级别

| 正在编写 | 先查哪些 `{级别}_word_relation_index.json` |
|----------|---------------------------------------------|
| N5 | 仅 `n5_` |
| N4 | `n5_` + `n4_` |
| N3 | `n5_` + `n4_` + `n3_` |
| N2 | `n5_`～`n2_`（依此类推） |

例：写 **N4 第 15 批** → 只从 N5、N4 全量关系索引取边，**不**去引 N3/N2 索引里的词（除非用户明确要求破例）。

实现说明：为了捕捉 N5 ↔ N4、N4 ↔ N3 这类跨级别关系，写作范围脚本可以读取 `all_word_relation_index.json` 作为综合索引源，但必须再按上表的允许级别、`written_keys` 和当前批次过滤；AI 最终仍只读过滤后的 `writing_scope/*_writing_relations.json`。

#### 2）「已编写」判定与每批更新

- **已编写**：`data/memory_methods/{级别}/batch_*_methods.json` 里，`mergedScene` **不是**默认占位场景（如含「在便利店门口，小田和朋友把刚发生的小事演了一遍」）的词条。
- **统计范围**：
  - 更低级别：该级别**全部**已落盘的批次文件；
  - 当前级别：仅 **batch_01 ～ batch\_{当前批号−1}**（正在写的这一批不算已编写，除非本条已有人工写好记忆法要当锚点）。
- **每开写新批次必须更新**（通常由用户说「开始编写」触发，AI 自动执行并先告知「脚本正在跑」；上一批「可以覆盖」之后，要写下一批时再跑，批号 +1）：

```bash
npm run memory:writing-scope -- --level n4 --batch 15
```

生成（脚本：`scripts/build_writing_scope_relations.cjs`）：

| 文件 | 用途 |
|------|------|
| `data/word_relations/writing_scope/{级别}_through_batch_{M}_written_keys.json` | 可作关系锚点的 `单词::读音` 全集（M=当前批−1） |
| `data/word_relations/writing_scope/{级别}_batch_{NN}_writing_relations.json` | **当前待写批次**每词的 `relations`（已过滤未编写 target） |

过滤规则（程序实现，AI 遵守输出即可）：

- 保留：`targetWord::targetReading` 在 `written_keys` 中；
- 默认还保留：**本批 40 词互相**引用（`includeSameBatchTargets: true`），便于同批 e12↔e39 这类链；
- 丢弃：索引里有边、但 target 在后续批次或仍是占位记忆法的词。

#### 3）AI 实际读取顺序

1. 用户说「开始编写」/「开始第 N 组」→ **先回复「脚本正在跑：`memory:writing-scope`（级别 / batch N）」** → AI 执行命令；跑完简报后再列记忆法。用户说「脚本我跑过了」→ 跳过执行，只确认 `writing_scope` 里 `generatedAt` 对应当前批。
2. 读 `{级别}_batch_{NN}_writing_relations.json` 写融合记忆法。
3. 仅当需核对某锚点是否已学，再查 `written_keys.json`。
4. 全量 `all_word_relation_index.json` / `all_word_relations_graph.json` 只供维护脚本或排查，**不要**绕过写作范围文件直接编故事。

### 关系索引使用原则

- 按单个词只取过滤后最相关的前几条关系，不要把全量索引塞进上下文。
- `*_relation_edges.json` 与全图主要给程序画链路图；`data/word_relations/sources/*_vocab.json` 是词表源，不是记忆法批次。
- 关系索引是「找线索」，不是「替 AI 完成记忆法」。同字、固定读音、词族关系只能解释为什么有关，不能单独替代谐音、假名块、字形或生活小戏。
- `same_kanji_different_reading`、透明汉字、固定读音类关系默认降权为辅助材料：除非它能和读音钩子融合成故事，否则不要把它当主记忆法。
- 每个词最多选择 1～2 条最高价值关系写进故事；不要堆砌同族词列表。若关系太多，优先选择能帮助区分发音或意思的那一条。
- **关系不等于主记忆法，但关系必须给用户看见**：审阅稿里即使某条关系没有被选进主记忆故事，也不能直接消失。每个词写完主记忆法后，必须复查 `relations` 中的高价值边，并用 `关联：` 按关系类型精简列出，尤其是同音不同字、同字不同音、读音前缀、浊点差、相似假名、反义/同场景词。用户需要看到这些链路，才能判断是否应该把词放在一起记。
- **关联词必须解释差异，不准只列关系**：`关联：` 行不能只写「A 和 B 同音/同字/相关」。必须说明差异如何帮助记忆：同音不同字要讲汉字、用法或意思差异；同字不同音要讲读音和含义分工；相似假名/浊点差要指出哪一拍、哪一个音改变了意思；反义/同场景词要说明场景里谁负责什么。如果解释不出差异，宁可降级为辅助提醒，不要硬写进主记忆法。
- **被降权的关系也要反思是否展示**：同字不同音、固定读音类关系可不进主故事，但如果能帮助辨认词族或避免混淆，审阅稿仍要列出。例如 `预约｜予約（よやく）` 必须列出 `予定（よてい）`：二者共享「予」且都读 `よ`，一个是预约，一个是预定/计划；不能因为主记忆用了谐音就漏掉这条关系。
- **遇到已编写过的关系词，必须回查该词正式记忆法的 `reviewTip`**：不能只贴关系类型、edgeId 或「共享汉字」。先在 `data/memory_methods/{级别}/batch_*_methods.json` 或汇总文件中找到目标词，读取它已确认的 `reviewTip`，再判断能否和当前词合成一条故事。
- 审阅稿中若引用已学词，优先显示为：`🔗 已学：词（读音）：reviewTip`，然后再写「本词如何借它记」。若用户标记 `bx序号`，表示该关系仅审阅参考，不写入 JSON。

### 融合记忆法（谐音 + 关系索引）

查到关系索引后，AI 必须把索引关系转化为可记忆的故事，而不是只列出“它和某词有关”。**编写时**仍要两条线都想过；**展示给用户时**只输出一条已融合的记忆法，不再并列「谐音版 / 索引版」。

#### 直播课方法论补强：先拆元素，再混用方法，再融合成一条

- **先拆元素，不要整词硬编**：每个词先拆成可处理的元素，包括汉字、假名块、长音/促音/浊点、已学词块、外来语来源、固定读音和关系锚点。拆分后再判断哪些元素值得使用；不要求把所有元素都用完，但不能跳过拆分直接编一个泛泛故事。
- **混用方法，不做六选一**：一个词不是只能用一种方法。可以对不同元素分别使用谐音、假名拆分、汉字直觉、外来语、固定读音、关系索引、对比辨析等方法；但最终必须合成**一条**主记忆法，而不是给用户并列多个版本。
- **所有元素都要服务 A → C → B**：拆出来的元素必须能产生 C（声音钩子、字形画面、差异点、关系小戏或生活场景），再从 C 落回 B（中文意思）。不能为了展示“我拆了很多”而堆元素。
- **融合稿优先写成同一个小戏**：如果一个词同时用了谐音和关系词，不要一段讲谐音、一段讲关系。优先把它们放进同一场景里，让用户从一个画面同时想起读音、差异和意思。

#### 编写时（内部，不分开给用户看）

对每个目标词，先在脑中或草稿里分别过一遍，再合成一条：

1. **谐音 / 读音线**（必考虑）：
   - 优先从目标词读音出发，找自然中文谐音或拆分谐音。
   - 每个词必须先内部生成候选：`整体谐音候选`、`拆分谐音/假名块候选`、`不用谐音原因` 至少完成其中两项；不能因为查到关系索引就跳过读音线。
   - `reviewTip` 有自然谐音时仍用：`发音 - 谐音 - 联想过程 - 单词意思`。
   - 整体谐音不自然则拆 2～3 段；仍不自然再换假名字形、汉字直觉、外来语、固定读音。
   - **假名内含已知词块时优先拆出来**：不要只盯汉字。若目标词读音里藏着已经学过的完整假名词、固定读音或高频词块，可以按假名拆分并绑定含义；例如 `羨ましい（うらやましい）` 这类词，读音内部可先找 `うら`、`やま/山`、`しい` 等可理解词块，再决定是否配合谐音，不要为了中文谐音牺牲读音准确。
   - **谐音候选必须先过假名/罗马音校验（N4 Batch 21 教训）**：提交前把读音拆成假名块或罗马音（如 `ふつう=futsuu`、`ひらく=hiraku`、`あたためる=atatameru`），再读中文候选。中文钩子至少要贴住开头音、主要元音和音节顺序；若只是在意思上能圆回来但声音不贴，不能标为谐音，只能改成汉字直觉、固定读音、外来语、关系记忆或普通场景联想。
   - **禁止“意译型伪谐音”**：例如 `ふつう` 不能谐音成“服从”（`tsuu` 与“从”偏差大），`ひらく` 不能谐音成“一拉开”（多出“一拉”，且 `hi-ra-ku` 未被保留），`あたためる` 不能为了“温”硬写“啊烫烫没冷了”。如果无法对照原读音，就先写罗马音再重新选钩子。
2. **关系索引线**（必查，有则必用，且遵守「关系编写范围」）：
   - 只使用 `writing_scope/*_writing_relations.json` 里给出的 `relations`（已去掉未编写 target）。
   - 搜索和关系查找不能只查汉字，必须同时查 `word`、`reading`、`readingRomaji`、关系目标词和关系目标读音。用户搜 `かえる`、`カエル` 或 `kaeru` 时，都应命中同一批同音词。
   - 至少选 1 条最高价值边编进故事；优先级：同音不同字 > 读音前缀词块 > 相似假名/浊点差 > 自他动词/词形派生 > 同字不同音/固定读音。后两类必须降权为辅助，不可单独成稿。
   - 对每条选中的已学关系边，先查目标词 `reviewTip`，再决定是否融合。最终输出不能只有「它和某词有关」，必须体现：旧词的记忆链是什么、当前词借旧词怎么更好记。
   - **读音前缀词块（`reading_prefix_chunk`）**：当短词读音从长词读音开头开始完整包含，且短词至少 2 个假名时，必须视为高价值拆分线索；例如 `妻（つま）` 是 `つまらない` 的开头词块，可以把 `つま` 先拆出来，再接后面的 `らない` 编故事。只从开头算，默认不把中间包含（如 `あつまる` 里有 `つま`）当强关系，避免链路图变乱。
   - 写法不是“X 和 Y 有关系”，而是把**已学过**的相关词放进同一个小故事，用汉字、场景、用途或假名差异区分含义。
   - 过滤后 `relations` 为空：可借 `written_keys` 或**本批其他词**作簇锚；`🔗` 标明锚词；勿引用后续批次或占位词。
   - 展示可附（**仅对话审阅，不写入 JSON**）：`索引：单词::读音 → edgeId → 相关词（写作范围已过滤）`。

#### 解释不是记忆法（硬性质量门）

以下内容只能作为辅助，不能单独作为最终稿：

- `数学=数+学=数学` 这类汉字拆分复述。
- `ピンク=pink`、`コンピューター=computer` 这类外来语来源复述。
- `生=せい`、`書=しょ` 这类固定读音说明。
- `A 和 B 同字/同音/同族` 这类关系索引复述。
- **汉字和读音没有关系时，禁止把汉字拆分当主记忆法**：不能写成 `家事=家+事`、`性格=性+格` 这类只解释意思、不解决读音的稿子。透明汉字最多用于最后确认意思，主链必须另有读音钩子、假名拆分、固定读音、同音关系、外来语来源或生活场景。若只能靠汉字解释意思，这条记忆法必须返工。
- **简单汉字拆分必须加读音钩子和场景，否则不合格**：不能写成 `食卓=食(しょく)+卓(たく)=饭桌` 这种低质量解释。应先标注已学固定读音或关系词，再给未解决部分补谐音/画面，例如 `食卓(しょくたく)` 要先接 `食事` 的 `食=しょく`，再把 `たく` 谐音成“他哭”，设计“孩子因为饭难吃在餐桌旁大哭”的场景，最后落到“饭桌、餐桌”。
- **提交前逐条问一句：这条有没有真正解决发音？** 如果主链只是复述汉字意思、固定读音或关系索引，没有让用户从读音走到画面，再从画面走到意思，必须返工。尤其是透明汉字词，不能因为意思好猜就省略声音钩子。

合格稿必须满足 A → C → B：

- A 是目标单词或读音；
- C 是声音钩子、字形画面、假名差异、关系词小戏或生活场景；
- B 是中文意思。

如果用户看到单词后不能在 3 秒内从 A 想到 C，再从 C 想到 B，就要重写。透明词、外来语和固定读音词也至少要补一个微场景、用法差异或易混提醒；否则只能算“解释”，不算本平台的记忆法。

每条记忆法还必须通过「三化」检查：

- **具体化**：故事里至少有明确的人、地点、动作、物品或结果，不能只写抽象概念。
- **新奇化**：画面要有一个不寻常但能理解的钩子，让用户愿意多看一眼；不要写成普通词典解释。
- **情绪化**：最好能让读者产生一点反应，比如好笑、尴尬、惊讶、紧张、痛感、心疼或恍然大悟。完全没有情绪的句子，要补动作、后果或冲突。

如果一条记忆法没有具体画面、没有新奇点、没有情绪反应，默认不合格；先重写 `mergedScene`，再压缩成 `reviewTip`。

**场景强度返工标准（N4 Batch 20 教训）**：

- 谐音故事不能只做到“解释得通”，必须让用户一读就进入场景：有人物、有地点或处境、有动作、有后果，最好还有焦急、尴尬、生气、空落落、惊喜、心疼等情绪。
- 标准链路写成：`读音钩子 → 生活冲突/具体画面 → 情绪反应或结果 → 单词意思`。缺少“冲突/情绪/后果”的，即使发音谐音正确，也要返工。
- 同音或相近词要尽量放进同一场景，而不是只列关系。例如 `機械/機会`：机器一开轰隆隆运转，需要人在旁边看守防错，于是产生工作机会；一台機械带出一个機会。
- 拆分记忆也要带画面。例如 `心(こころ)` 可拆 `ここ=这里` + `ろ≈落`：春节后家人离开，这里突然空了，心里空落落。
- 用户给出方言、俗语或生活经验时，优先保留并场景化。例如 `壊す(こわす)` 可用“kou娃撕”：孩子把珍贵东西撕坏，家长气到一直指责；从愤怒场景落到“弄坏”。
- 透明汉字也要补桥梁。例如 `翻訳(ほんやく)`：`本=书`，`訳=解释/译`，把书里的话解释成另一种语言；再用“宏大、高雅、炫酷”钉住 `ほん・や・く`。

**点名批改与固定读音串联（N4 Batch 22 教训）**：

- 用户审阅一组后，若明确说「提到的序号才修改，没有提到按上一版」，则只改用户点名条目；未点名词必须保留上一版，不要顺手重写。
- 透明汉字词不能只写「汉字就是意思」，必须把固定读音串到已学词里。例如 `医学(いがく)`：`い` 对应「医」，`学=がく` 可接 `学生(がくせい)`；`意見(いけん)` 可接 `意思(いし)` 的 `意=い`；`会議室(かいぎしつ)` 要接已学 `会議(かいぎ)` 和 `教室(きょうしつ)` 的 `室=しつ`；`用事(ようじ)` 要接 `火事/家事` 的 `事=じ`。
- 遇到浊化要明确写出原音和变化。例如 `水` 本来常读 `すい`，放到 `洪水(こうずい)` 后面变成 `ずい`，要用“清水变浑水、すい 变 ずい”这类画面钉住。
- 同根性别词要一起记。例如 `娘(むすめ)` 可记“母思妹”=女儿，`息子(むすこ)` 可记“母思子/母思ko”=儿子；`むす` 是共同开头，`め/こ` 用来区分女儿/儿子。
- 已学动词和名词化词要联动更新。例如 `手伝う(てつだう)` 和 `手伝い(てつだい)` 都可用“铁子打我，赶紧喊铁子来帮忙”；`手伝い` 是 `手伝う` 的名词化，表示帮忙这件事。

**固定读音与词形派生串联（N4 Batch 24 教训）**：

- 数字和高频汉字有多读音时，必须主动标注读音分工，再进入故事。例如 `四` 常见 `よ/し` 两条线：`四日(よっか)`、`四つ(よっつ)`、`四(よん)`，但 `四季(しき)` 读 `し`；`十` 在 `渋滞(じゅうたい)` 中可借 `十(じゅう)` 记“十台车堵住”。
- 固定读音要接已学词，不要孤立写“固定发音”。例如 `近=きん` 可接 `最近`，`園=えん` 可接 `公園(こうえん)`，`音=おん` 可接 `音楽(おんがく)`，`発=はつ` 可接 `発音(はつおん)`，但要提醒 `発展(はってん)` 这类例外读法。
- 已学动词的名词化、派生词必须优先沿用旧记忆链。例如 `引越し(ひっこし)` 是 `引っ越す(ひっこす)` 的名词化，应沿用“嘿磕死、搬家扛箱子膝盖磕死”的场景；`通り(とおり)` 要接 `通る(とおる)` 的“通路/路打通就能通过”。
- 用户批改中点出“前面学过”的词，必须先回忆旧 `reviewTip`，再把新词写成“旧词故事的名词化/派生/读音固定化”，不要重新编一条无关故事。

**旧词回修与动作原型串联（N4 Batch 25 教训）**：

- 用户在批改新批次时明确说“之前某批某词也要修改”，必须小范围回修旧批次正式 JSON，并同步对应 `all_*_memory_methods.json`；没有被明确点名的旧关联词只在审阅稿里引用，不擅自改旧文件。
- 遇到中文里仍能感到动作原型的汉字，要用“动作原型”串多义，不要只列义项。例如 `払う(はらう)` 可从“拂”的挥袖动作出发：挥手拂去、驱赶、清除；支付则像把账单甩走，最常用义仍先记“支付”。
- 同音不同字若已成固定故事，后续复合词必须回忆旧故事。例如 `ちゅうしゃ` 可串 `注射/駐車`：救护车晃动，护士喊司机停车后给患者注射；再接 `場(じょう/ば)` 的场所读音分工。
- 自他动词或词形对比要显式写差异：`まる` 多偏自动、自然而然发生，`める` 多偏他动、有人为意志参与。例如 `集まる(あつまる)` 是人自己聚集，`集める(あつめる)` 是主动把人或物聚起来。
- 透明组合也可以成为强记忆，但必须解决读音和语法功能。例如 `仕方(しかた)` 要拆 `仕=し（做）+ 方=かた（方法）`，`仕方ない` 是 `ない=没有`，所以“没有方法=没办法”；`着せる(きせる)` 要接 `着物/上着` 的 `着=き/ぎ`，再用 `せる=使` 说明“使别人穿上”。
- 若用户把已学词作为新词的谐音入口，优先按用户链路重写。例如 `昼(ひる)` 可由“黑路”反差记：白天太阳耀眼，没有漆黑的路；`昼間(ひるま)` 再接“黑路马”。

**派生词、复合词与旧故事复用（N4 Batch 26/27 教训）**：

- 新词如果是已学词的复合、名词形或派生形，必须先回忆旧词故事，再说明新词只是“加了什么/变成什么”。例如 `残る(のこる)` 要接 `残り(のこり)` 的“脑壳里还有剩余作业”；`遊び(あそび)` 要接 `遊ぶ(あそぶ)` 的“小孩啊一声跑到外面ぶんぶん乱跑”；`着る物(きるもの)` 要接 `着物/着せる/上着` 的 `着=き/ぎ`。
- 复合词里出现已学固定读音时，不要只写“固定读音记住”，要把旧词和当前词放进同一画面。例如 `口げんか` 要接 `喧嘩(けんか)` 的“铿咔吵架”场景，再说明前面加 `口(くち)` 就是只动嘴吵；`昼休み` 要接 `昼=黑路` 和 `休む=要死噜所以休息`，白天能休息的一段就是午休。
- 同音不同字或同读音词块要串成一组情绪画面。例如 `服/吹く/拭く` 都读 `ふく`，可以写成“大风把脏东西吹到服上，所以要拭く擦掉”；`洪水(こうずい)` 与 `香水(こうすい)` 要用清浊差：洪水是浑浊发臭的水，香水是稀释后清爽的香。
- 自动/他动对比必须放进同一动作，不要分散解释。例如 `倒れる/倒す`：塔自己倒是 `倒れる`，有人把塔弄倒是 `倒す`；`閉まる/閉める`：门自己关上是 `閉まる`，人主动关门是 `閉める`。`まる/れる` 常偏自动，`す/める` 常偏他动或人为动作，具体仍以词义校验。
- `場合/合う/会う` 这类同字、近义或易混关系不能只列“共享汉字”。要解释语义差异：`会う` 是见面，`合う` 是合适，`場合` 是事情发生时那个“场”和“合”的情况；如果用户把 `会/合` 混用，要在关联行纠偏。
- 用户点名“重新谐音/重新故事”时，优先保留用户给出的发音入口和情绪画面；没有点名的词，按上一版草稿保留，除非发现字段/OCR 明显错误。

**促音三连、长音差一字与谦让语画面（N4 Batch 30 教训）**：

- `っ` 促音词块要按开头音分组对比，不要只写“三个っ不一样”。例如 `ずっと/きっと/ぐっと`：`ずっと=直到(ず像滋——长线)`，`きっと=一定(き清脆)`，`ぐっと=使劲(ぐ浊音)`，三个っ靠开头音区分。
- 近形词要用“差一个假名/长音”钉住差异。例如 `規模(きぼ)` 和 `希望(きぼう)`：规模=希望的大小，希望要等待所以多一个长音う；`夢(ゆめ)` 和 `有名(ゆうめい)`：有梦是短音，有名多了长音像长期奋斗才出名。
- 透明汉字也要补画面，不能只列部件。例如 `主(おも)` 要串 `重い+心+田+思い`：背着沉重包袱，心里脑子里一直想，最重要的那个就是主因。
- 自他/自动花费对比要放进同一动作。例如 `掛ける(かける)` 谐音“挂给了”，可挂外套、打电话、花钱；`かかる` 是卡卡撸=自动花费，`掛ける` 是他动。
- 复合方向词要从已学词拆，不要重编。例如 `行き先(いきさき)`：`行き=去`，`先=前方`，一出门口就先问“一去先去哪”。
- 谦让语和礼貌表达要有具体开口画面。例如 `伺う(うかがう)` 谐音“我看看喔”，客气地对老师说能不能请教一下。
- `運` 字族要串运动/运转/自行车：`運動(うんどう)` 谐音“晕动”，跑完步晕得动不了；`運転(うんてん)` 的運也读うん；`自転車=自蹬车`。
- 曜日系列固定读 `よう`：`土曜(どよう)` 可记住校生周一拿钱、周中花光、周六吃土；曜在曜日、日曜、月曜里都读よう。

**反义词、字序颠倒与冷门词降噪（N4 Batch 28 教训）**：

- 遇到已学反义词时，要把两个词放在同一个对照里，而不是孤立解释。例如 `浅い(あさい)` 必须接 `深い(ふかい)`：朝光浅浅照进水面能看到底，和“深い=深”成反义。
- 字序颠倒词要直接标出顺序变化。例如 `国外(こくがい)` 和 `外国(がいこく)` 是同两字反过来：外国是外面的国家，国外是国家外面；不要重新硬编一条无关故事。
- 已学动词、名词或同音词要复用旧故事，并说明当前词的差异。例如 `変わり(かわり)` 要接 `変わる` 的“卡弯路”与 `代わり` 的“替代”；`贈り物(おくりもの)` 要接 `送る/贈る(おくる)`：送る偏送行，贈る偏赠礼；`運転手(うんてんしゅ)` 要接 `運転(うんてん)` 的“稳点”。
- 不常见或不适合重编的词可以明确标注“先认识即可”，但仍要给最小钩子。例如 `平仮名(ひらがな)` 可接已学 `開く(ひらく)` 的 `ひら=展开/铺开`，再提醒这个词不常见，先认识。
- 透明复合词也要从已学固定读音里找声音钩子。例如 `文化/文学` 里的 `文=ぶん` 要接 `文法(ぶんぽう)`，`化=か` 要接 `温暖化(おんだんか)`，`学=がく` 要接 `学生(がくせい)`；不能只写“文+化=文化”。
- 纯假名词如果没有汉字，要优先找可感知的音感或生活结果。例如 `すっかり` 可用“撕卡哩”：词卡被一张张撕完，最后全都没了；比单纯写“完全”更能记住。

**旧批次质量清洗（N4 前 24 组教训）**：

- 清洗旧批次时，`reviewTip` 禁止只写「固定读音」「汉字直觉」「汉字直译」「外来语直接对应」。即使是 `犯人`、`社会`、`飲食店`、`文字`、`コンピューター` 这类看似透明的词，也必须补一个能触发发音的小钩子和生活小戏。
- 合格的旧批次替换格式优先为：`读音 - 谐音/近音/来源 - 具体场景动作 - 单词意思`。固定读音和汉字意思最多放在辅助位置，不能再次写成「犯=はん，人=にん，所以犯人就是犯人」这种复述。

#### 展示给用户时（对外，一条记忆法）

- 格式仍为：`序号. 词语（意思，读音）：记忆法 - 单词意思`；同音/易混另起 `🔗` 或 `⚠️` 行。**不附例句**（`exampleSentences` 留到覆盖写入 JSON 时再写，审阅阶段无需在对话中列出）。
- **主记忆法一段**里同时体现：谐音或固定读音钩子 + 关系词对比或同字/同音差异（能编进同一小戏就不要拆成两段）。
- 若用了已学词，审阅稿要把旧词 `reviewTip` 贴出来或精简贴出核心链，再说明能否合并记忆。不要让用户只看到“以前学过某词”，却看不到以前那条记忆法。
- 主记忆法之后必须补一行 `关联：`，把未写进主故事但仍有助于记忆的关系词列出来；如果没有高价值关系，可省略。关联行按关系类型写清楚，不写技术字段。例如：
  - `关联：予定（よてい）=预定/计划，予約（よやく）=预约；「予」都读よ，都是提前安排。`
  - `关联：暑い/熱い/厚い 都读あつい；日字旁=天气热，火/熱=物体烫，厚=厚。`
- 需要追溯关系图时，可在记忆法后附一行简注：`索引：单词::读音 → edgeId/类型 → 相关词`（**审阅专用，覆盖时不写入 JSON**），不单独再列第二版故事。
- 用户批改某条时，默认是在改这条融合稿；若用户只要谐音或只要关系对比，按用户意见调整融合比例。

#### 写入 JSON 时（仅「可以覆盖」之后）

- `mergedScene`：1～3 句生活小戏，谐音与关系对比编进同一画面。
- `reviewTip`：一行主链（谐音或固定读音格式）+ 必要时 `🔗` 串关系词；勿再写「推荐：索引版」之类二选一标签；**勿写** `索引：` 开头整行、`edgeId`、写作范围/filtered 等审阅标记。
- **复习连续性**：已被用户确认过、已经能稳定触发回忆的 `reviewTip`，不要轻易重写。后续发现新关系、新例句或新解释时，优先把它们补进 `mergedScene`、`elements` 或 `🔗` 辅助提醒；只有原 `reviewTip` 发音错误、含义错误、故事不通、用户明确要求重写时，才替换主链。复习时最重要的是让用户反复走同一条 A → C → B 路径，而不是每次看到不同解释。
- `elements`：可列出谐音拆段、固定读音、关系锚词；**勿写**审阅专用 `索引：` 行或裸 `edgeId`（除非用户明确要求保留技术字段）。
- `exampleSentences`：覆盖时写入（审阅阶段不必在对话展示）；每词至少 1 条，格式见下节。

示例（融合后，对用户只展示这一条）：

`契機（けいき）`

- 记忆法：`けいき - 谐音“开机” - 小田上台自我介绍像按下人生开机键；同音 **景気(けいき)** 是经济气氛变好，**契機** 是事情开始转好的那个启动点，一个管市场一个管转机 - 契机/转机`
- 索引注：`契機::けいき` → 同音→景気(けいき)

## 用户确认覆盖时的写入规则 ⚠️

### 标准流程（每轮批改后必遵守）

```
用户提出修改意见
      ↓
AI 按意见修订（含未点名的词，保留 AI 本轮最终版）
      ↓
AI 向用户展示【完整 40 词】记忆方法（1～40 逐条列出，不可只发被改的词；每条为融合稿，不分谐音版/索引版；不含例句）
      ↓
用户审阅 → 继续提修改 / 或明确说「可以覆盖」「确认」
      ↓
收到确认后，才写入 batch_XX_methods.json（40/40 全量覆盖）
      ↓
验证无默认占位场景 → 向用户汇报「第 XX 组已全量写入，40/40 条，无遗漏」
      ↓
用户说「开始编写」下一批：AI 告知「脚本正在跑」→ 自动执行 memory:writing-scope（--batch <下一批号>）
```

**关键约束：**

1. **审阅阶段禁止修改正式 `batch_*_methods.json`**（与标准链路第 4 步相同）：展示、往返修改期间，只改对话稿，不动正式批次文件。
2. **每次用户提出修改之后**，必须先给出该批次 **完整 40 个单词** 的记忆方法全文，再等待用户确认；**不得**在用户未确认前写入 JSON。
3. 用户只点名修改了部分单词 → 展示与写入时仍须包含 **全部 40 条**（未点名的词用 AI 本轮给出的最终版）。
4. **不能只写用户明确提到的词**，未提及的词同样是本轮最终版，确认后一并覆盖。
5. 每次覆盖后必须验证：确认所有 40 条的 `mergedScene` 均为自定义内容，不能有默认占位场景（如「在便利店门口，小田和朋友把刚发生的小事演了一遍，读音 X 作为固定读法记住」）。
6. 覆盖完成后向用户汇报：「第 XX 组已全量写入，共 40/40 条，无遗漏」。
7. **审阅阶段不向用户展示例句**；覆盖写入时须补齐每条 `exampleSentences`（见下节格式）。
8. **关系词写入规则（bx 标记）**：记忆文档中找到的关系词，**默认在用户确认覆盖后写入 JSON**。只有用户在序号前标记 **bx** 时，才不写入该词的关系词。例如 `bx27` 表示不把第 27 条找到的相关单词写进 JSON。未标记 bx 的词，其关系词照常写入 `reviewTip` / `elements` / `mergedScene`。

**触发「开始编写」、由 AI 自动跑脚本的用户用语示例：**「开始编写」「开始第 15 组」「开始 batch_15」。

**跳过自动跑脚本的用户用语示例：**「脚本我跑过了」「不要跑脚本」「直接用现有 writing_scope」。

**触发「可以写入 JSON」的用户用语示例：**「可以覆盖」「确认」「覆盖到第 X 组」「写入」。

**不算确认的用语：** 仅提出新的修改意见（如「e2 再改一下」）→ 继续修订并再次展示完整 40 词，仍不写入。

`exampleSentences` 统一使用数组格式：

```json
[
  {
    "ja": "日本語の例文です。",
    "zh": "中文翻译。"
  }
]
```

旧批次里如果已经存在 `exampleSentence`、`examples`、`sentences` 或 `exampleSentences`，先保留原字段；新批次统一使用 `exampleSentences`。

## 记忆方法风格

每个词优先使用三层结构：

1. 发音联想：优先找自然、好记的中文谐音。
2. 小故事绑定：把谐音变成有趣、具体、生活化的小故事，让故事自然导向单词意思。
3. 汉字/固定读音辅助：中文能直接看懂的，用汉字本义、固定读音或外来语补强。
4. 易混控制：和相近词、相近读音、相近语法做对比提醒。
5. 相似词成对记忆：当两个词只差几个假名、一个点或一个长音时，优先把它们放在一起，通过“差异点”绑定意思差异。
6. 多读音追踪：同一个汉字如果在前面批次出现过不同读法，必须标记并积累；尤其是 `書` 这类常见字，见到新读法要写进元素和规则，防止下次不会读。

优先级：

1. 用户提供的谐音和故事最高优先级，直接吸收。
2. 自己生成时，先找自然中文谐音，再把谐音变成一个具体小故事。
3. 如果有罗马音/英语/外来语相似，也可以作为强记忆点，比如 `namae≈name`、`neko→Nike`、`ニュース≈news`。
4. 汉字直觉和固定读音用于补强，不要压过好玩的谐音故事。
5. 谐音生成必须按顺序尝试：先多试几个整体谐音，选发音最贴近、最容易一眼想起的；如果整个单词的发音直接谐音不自然，优先把发音拆成 2 到 3 段分别谐音，再合成故事；如果拆开仍然不合理，就改用假名字形、汉字直觉、固定读音、外来语或生活联想，不要硬凑。比如 `つまらない` 拆成 `つまら=吃麻辣` + `ない=没有`，`てがみ` 拆成 `特 + 加 + 密`。
6. 如果两个单词非常相像，优先找“少了什么/多了什么/换了什么”的视觉差异来记；比如 `ちょっと` 比 `ちょうど` 少了一个点，所以是“一点”，`ちょうど` 正好多了一点，所以是“正好”。
7. 当两个单词假名十分接近时，可以使用“字型变化法”：观察假名多了点、少了点、弯了一下、转了一圈、清音变浊音等变化，把这个变化和意思差异绑定。
8. 当两个词只是假名增减且意思相近时，优先考虑语法差别：比如名词/状态词加 `る` 变动词，名词后面加动词结尾变成动作。
9. 当两个词同音或读音完全一样但意思不同，要集中成组串联含义，靠汉字、场景和用法区分，不要分散硬背。
10. 当两个词意思相反或成对出现，可以编一个谐音梗把两边一起钉住，比如左/右、早/快、花/鼻。
11. 当两个词意思基本相同但语气、礼貌程度或使用场景不同，也要放在一起记；重点写清“都是什么意思”和“差别在哪里”，比如 `みなさん/みんな` 都是大家，`みなさん` 更礼貌，`みんな` 更口语亲近。
12. 做关联记忆时，不能只写“这两个词有关”。必须继续拆：比较假名增减、浊点、长音、促音、礼貌词尾、字形负重、谁跑得快/慢、谁更正式/亲近，再把差异编成小故事。比如 `また/まだ`：`た` 卸了两点包袱跑得快，所以“又来了”；`だ` 背着两个点走不快，所以“还没到”。

常用方法标签：

- `TYPE A1`：汉字直觉
- `TYPE B2`：发音联想
- `TYPE B1`：假名/字形联想
- `外来语`
- `固定读音`
- `关联记忆`
- `语法记忆`
- `对比记忆`

## elements 写法

- 每个词 1 到 4 个记忆点即可。
- 不要把每个假名都机械拆开，只拆真正有记忆价值的部分。
- 汉字透明的词要短，难混的词要多写对比。
- 外来语优先说明英文或来源词。
- 固定组合要直接提醒整体读音，比如 `今年=ことし`。

## mergedScene 写法

- 用 1 到 3 句中文画面。
- 必须有具体人物、场景、动作、物品或情绪。
- 可以荒诞、搞笑、夸张，只要能帮助记住。
- 最好写成“一词一小戏”：谁在什么地方，因为谐音做了什么事，最后自然落到单词意思。
- 若索引里有高价值关系词，把对比/同字/同音差异编进**同一段**小戏，不要另起一段只讲关系而不讲故事。
- 用户给的生活化故事要尽量保留原味，比如老婆回答、奴家脱衣服、戒烟砸烟灰缸、给鸭一张卡。
- 不要写空泛句，比如“这个词很好记”。

## reviewTip 写法

- 第一行优先判断是否有自然、好记、不生硬的谐音。
- 有自然谐音时，必须使用格式：`发音 - 谐音 - 联想过程 - 单词意思`。
- 有罗马音/英语相似时，使用格式：`发音 - 罗马音/英语相似点 - 联想过程 - 单词意思`。
- 没有自然谐音时，不强行写“无谐音”，改用汉字直觉、固定读音、外来语、语法、对比记忆或生活场景。
- 透明汉字词、外来语、固定组合优先直接解释，不硬凑中文谐音。
- 直接解释后必须补一个记忆桥梁：微场景、动作、差异点、易混提醒或关系词故事。只写“汉字就是意思”“外来语来源于英语”“固定读音记住”不合格。
- 如果 `reviewTip` 读起来像词典解释，而不是 `发音/字形 → 画面 → 意思` 的回想链，必须重写。
- `reviewTip` 是复习时的主链，稳定性优先。除非有明显错误或用户要求，不要把已经确认过的主链换成另一个新故事；可以追加 `🔗` 或 `⚠️`，但不要破坏原本能唤起记忆的路径。
- 用 `⚠️` 标常见坑。
- 用 `🔗` 串联相关词。
- `reviewTip` 里可以放短例句，但结构化例句必须放进 `exampleSentences`。

## exampleSentences 写法

- **审阅阶段**：不在对话中向用户展示（不写「例句：…」块）；用户只审记忆法正文。
- **覆盖写入阶段**：每个词至少 1 条例句，写入 JSON 的 `exampleSentences` 字段。
- 例句优先贴合当前学习阶段；没有特别说明时，先用简单自然的基础句，不写复杂从句。
- 例句要自然、短、能直接体现单词用法。
- `ja` 写日语，`zh` 写中文翻译。
- 动词优先给真实搭配，比如 `歯を磨きます`、`バスに乗ります`。
- 名词和形容词避免机械套 `これは...です`，能给场景就给场景。

示例格式：

`こたえる - 谐音“可太爱了” - 老婆问爱不爱她，你回答“可太爱了” - 回答`

`はいざら - 谐音“害了，砸了” - 戒烟的人看见烟灰缸心痒，干脆把它砸了 - 烟灰缸`

`なまえ - 罗马音namae像英语name - 表格上的name栏就是写名字 - 名字`

`今月：今固定读こん，月固定读げつ；现在这个月就是今月=这个月`

`シャワー：外来语 shower，水从喷头冲下来=淋浴`

`⚠️ 今年特殊读ことし，不读こんねん。`

`🔗 今月、今週、今晩是一组。`

`つまらない - 拆成“つまら=吃麻辣 + ない=没有” - 四川人饭里没有吃麻辣，就会觉得很无聊 - 无聊的`

`てがみ - 拆成“特 + 加 + 密” - 一封特别加密的信 - 信`

`でる - 谐音“得喽/得噜” - 不上班被父母天天念叨，最后大喊“得喽”才出门 - 出去`

`でんわ - 谐音“等哇” - 为了特殊任命通知，在电话前等哇等哇 - 电话`

`どうぶつ - 谐音“都不吃” - 因为都是保护动物，所以都不吃 - 动物`

`とおか - 谐音“读卡” - 公司每月十号发工资，员工都在十号读卡查工资 - 十号`

`ときどき/どきどき：ときどき=有时；どきどき=心动/心跳。可以联想“有时对她很心动”，どきどき前面的两点像心脏跳动。`

`とけい - 谐音“躲开” - 在时间面前任何人都不可能躲开，时钟显示时间 - 钟表`

`ところ - 谐音“偷可乐” - 小孩总去固定地方偷可乐 - 场所/地方`

`となり - 谐音“偷哪里” - 两个小偷商量偷哪里，另一个回答邻居家 - 旁边/隔壁`

`ともだち - 谐音“偷摸拿鸡” - 好朋友就是一起偷摸干搞怪事的哥们 - 朋友`

`どようび - 周一到周五胡吃海喝，周六没钱只能吃土 - 周六`

`撮る(とる) - 谐音“偷录” - 偷偷录制或者拍摄视频 - 照相/拍摄`

`せびろ - 谐音“帅毙了” - 男人一穿上西服就显得帅很多 - 西服`

`せんたく - 谐音“掀他裤” - 孩子裤子太脏又不想换，只好掀开洗洗 - 洗衣服`

`そうじ - 谐音“扫圾” - 扩展成打扫垃圾，所以是打扫 - 打扫`

`だいがく - 谐音“太开阔” - 第一眼来到大学校园，发现真的很开阔 - 大学`

`たいしかん - 谐音“他一细看” - 他一细看发现竟然是大使馆 - 大使馆`

`だいどころ - 谐音“打一桶可乐” - 结合ところ“偷可乐”，小孩经常去厨房偷可乐 - 厨房`

`だす - 谐音“打死” - 用极端抢劫故事记“逼到最后才拿出财宝” - 拿出/取出`

`たつ/たて：たて就是たつ站起来后的样子；站起来就变成竖起来的东西。`

`はいる - 谐音“嗨一路” - 进入大堂前跟很多人打招呼说hi，说了一路才进去 - 进入`

`葉書：葉=树叶，書=书信；古代文人互送明信片，会把当地树叶夹在书信里。注意書在図書館读しょ，在葉書读がき。`

`はじめ组：始まる/初め/始め/初めて一起记。始读haji，可用“哈尔滨吉林都开始修马路了”记开始；初め偏最初，始め偏开始动作，初めて是初次。`

`はなし/はなす：はなし是名词“话”，はなす是动词“说话”；す结尾常见于动词。`

`はやい：早い/速い同读。因为跑得快所以到得早；也可谐音“好压抑”，每天很早上班还跑得很快。`

`はる组：春/貼る一起记。开春过春节，大家哈大笑，还要把春联贴上去。`

`晴れ/晴れる：晴れ是晴天状态，晴れる是后面加る动词化，表示放晴。`

## 质量红线（N4 Batch 03 教训）

**谐音生成必须遵守：**

1. **发音准确性第一**：谐音必须基本符合原词发音，不能为了故事牺牲发音准确性。比如 `すみ` 不能谐音成”扫地”（发音不符），应谐音”私密”。
2. **生活逻辑**：故事要符合日常生活实际，不能胡编乱造。
3. **情绪化**：故事要能让读者有情绪反应（搞笑、惊讶、尴尬、痛感等）。
4. **谐音必须展开成故事**：不能只写「谐音成 X」就结束。谐音是钩子，后面必须接 1～3 句具体小戏——有人物、动作、后果，读者从故事里才感受到情绪。⚠️ 只有谐音没有故事，视为不合格。
5. **不是每个词都要谐音**：汉字透明、外来语明显、固定读音稳定、有典故/生活场景的词，优先用汉字直觉、外来语、固定读音、关联记忆、典故记忆，不必硬凑谐音。
6. **汉字拆分记忆法**：遇到谐音拆分奇怪的，按字本身在日语中的含义做拆分。比如 `押し入れ` 不硬凑谐音，而是拆成 `押し=按` + `入れ=放入`。
7. **没有谐音就不要硬凑**：用固定读音、字形拆分、外来语等其他方法。
8. **别扭谐音要换法**：输出前若某词谐音读着拗口、故事圆不回来、自己念一遍都尴尬，立即换谐音或改用非谐音记忆法，不要凑合提交。
9. **汉字意思不能冒充读音谐音（N4 Batch 01 教训）**：汉字直觉、中文释义联想只能辅助记意思，不能代替发音钩子。若中文联想和假名读音明显不符（如「隅」可联想扫地，但 `すみ`≠扫地），**禁止**标为谐音；应换贴近发音的钩子（私密）、固定读音、拆分或场景记忆。

## 拆分谐音记忆法（N4 Batch 04 重点）

当整词谐音不自然时，优先把发音拆成 2～4 段，每段分别找贴近的中文谐音，再合成故事。

**写法要求：**

- 每段谐音必须在 `elements` 里单独列出，标注 `拆分谐音` 或 `TYPE B2`。
- 每段谐音要基本贴合该段假名发音，不能只看意思硬凑。
- 合成故事要让各段谐音都出现，并自然落到单词意思。

**典型示例：**

`はつげん(発言) - は=八 + つ=次 + げん=敢 - 发言八次还敢说话 - 发言`

**延伸用法：**

- 段数按实际发音切，不机械按假名个数切。
- 某段若已有固定读音（如 `げん=言/元`），可先写固定读音，再补谐音。
- 拆分后仍不自然，就改用汉字直觉、固定读音、字形联想，不要硬凑。

## 字形记忆法（N4 Batch 04 重点）

当谐音弱、但假名字形有视觉特征时，用字形/翻转/象形联想绑定意思。

**写法要求：**

- 在 `elements` 标注 `字形联想`。
- 描述要具体：怎么转、像什么、对应什么意象。
- 可与汉字直觉叠加，但不替代读音绑定。

**典型示例：**

`ひ(火) - ひ 倒过来看，像一团熊熊燃烧的🔥 - 火、火焰`

**延伸用法：**

- 假名「多一点/少一点/浊点」可联动对比记忆（见相似词规则）。
- 字形联想适合单假名、短词；长词优先拆分谐音或固定读音。
- 故事仍要生活化、有画面，不要只写「它像火」。

## 典故记忆法（N4 Batch 05 重点）

当单词来自中日共享典故、历史故事或文化梗时，优先用典故绑定意思，**不必硬凑谐音**。

**写法要求：**

- 在 `elements` 标注 `典故记忆` 或 `文化联想`。
- 故事写清人物、说错/反转、他人感叹，再落到日语词义。
- `reviewTip` 可写「典故：……」便于复用。

**典型示例：**

`さすが(流石) - 典故：孙楚本想“枕石漱流”说成“漱石枕流”，还能圆回来，王济叹“真不愧是你” - 真不愧、钦佩`

**延伸：**

- 日漫固定语（如 `いただきます`→いただく）走文化联想，不硬造谐音。
- 谐音别扭时，优先换典故、关联、固定读音，见「输出前最终校验机制」。

## 谐音选词：生活实际 + 有情有感（N4 Batch 04 重点）

选谐音时，不只问「发音像不像」，还要问「这谐音能不能引出真实生活和真实情绪」。

**优先选择：**

- 和生活场景强相关（如 `がんたん→感叹`，新年感叹又老一岁）。
- 能调动情绪（无奈、尴尬、生气、好笑、温暖、惊讶）。
- 故事和谐音一致，不靠额外解释圆回来。

**反面示例：**

- `がんたん` 谐音「肝叹」——发音虽近，但「肝」不自然，情绪也不如「感叹」贴新年场景。
- 应选 `がんたん→感叹`：新年第一天感叹又老一岁，有无奈、有共鸣。

**常见整词谐音不拆分：**

- 若整词谐音已是高频、公认的记法（如 `すばらしい→斯巴拉西`），直接用整词谐音 + 短故事，不必再拆段。
- 拆分是为了解决「整词谐音不自然」；不是每个词都要拆。

## 输出前最终校验机制（必做）

每一批记忆方法写完后，**逐词**过一遍下面三道关；不过关就改，不要直接输出给用户。

| 关卡 | 标准 | 不过关怎么办 |
|------|------|--------------|
| 1. 谐音现实性 | 谐音符合原词发音，且能在真实生活里说出来 | 换谐音或改拆分 |
| 2. 故事一致性 | 故事由谐音延伸，逻辑符合日常实际 | 重写故事，不硬圆 |
| 3. 情绪调动 | 读者能感到搞笑、惊讶、尴尬、生气、无奈、温暖等 | 加强具体人物/动作/后果 |
| 4. 故事展开 | 谐音后必须有完整小戏，不能只有谐音一句 | 补写 mergedScene，加人物和后果 |
| 5. 方法匹配 | 该词是否真的需要谐音；谐音是否别扭 | 换固定读音/外来语/典故/关联；换谐音 |

**校验示例（Batch 04）：**

- ✅ `だんぼう→单薄`：冬天穿单薄靠暖气——现实 + 共鸣 + 冷。
- ✅ `ゆるす→有露丝`：出轨不能原谅——现实 + 愤怒 + 好记。
- ❌ `ちから→空气`：发音偏差大、故事牵强——应改 `气卡啦`。

## 常见固定读音记录

遇到常见汉字读音，要在方法里顺手标注，方便后续批次复用：

- `今`：在 `今月/今週/今晩` 中常读 `こん`。
- `月`：在 `今月` 等月份相关词里常读 `げつ`。
- `週`：常读 `しゅう`。
- `時`：在 `時間` 中读 `じ`。
- `間`：在 `時間` 中读 `かん`。
- `生`：大多数常见复合词里可读 `せい`，如 `先生/生徒`；遇到生相关词先考虑这个读音。

## 同音不同字联想辅助记忆

### 原则

日语中存在大量**同音异字词**（读音完全相同、汉字/写法不同的词）。处理每个新单词时，必须主动检测它的读音是否与已学词重叠，若有重叠，探讨能否互相辅助记忆。

**同音不同字的判断标准是罗马音归一，不是只看汉字或原始假名字符串。** 例如 `かえる`、`カエル`、`kaeru` 都归一为 `kaeru`；`帰る/換える/変える/代える/返る/蛙` 这组应被当作同音不同字一起提醒。关系检索也必须支持假名和罗马音输入，不能出现只搜汉字有结果、搜 `かえる` 没结果的情况。

**处理规则：**

1. 生成记忆方法时，同步检测该词读音的罗马音是否命中已学词（见下方对照表）。
2. 若有同音词，在向用户展示时**额外一行**标注：
   - `🔗 同音：X(読み)＝Y(意思)`——可辅助联想记忆时用此格式
   - `⚠️ 同音：X(読み)＝Y(意思)`——意思差异大、容易混淆时用此格式
3. **展示时标注，覆盖时默认写入 JSON**：
   - 向用户展示记忆方法时，每词检测同音并**另起一行**标注（见上方格式）。
   - 用户说「可以覆盖/确认/写入」时，**同音联想一并写入**该词的 `reviewTip` 或 `elements`（或融入 `mergedScene`），与记忆法一起覆盖进 `batch_XX_methods.json`。
   - **例外**：用户明确说「这个同音不覆盖」「eX 同音不写进去」等 → 该条同音信息**不写入** JSON，其余照常覆盖。
4. 每发现新的同音对，更新本节对照表，格式：`読み | 词A | 词B | 记忆策略`。

## 难度规则

- `difficultyStars: 1`：汉字透明、外来语明显、读音稳定。
- `difficultyStars: 2`：纯假名、需要谐音、容易和相近词混。
- `difficultyStars: 3`：多义、多读音、用法抽象、特别容易混。

## sceneScore 规则

- `specific`：画面是否具体。
- `emotional`：是否有幽默、惊讶、紧张、尴尬、痛感、温暖等情绪。
- `personal`：是否能贴近日常、学习、考试、动漫、家庭、食物、钱、学校、旅行等经验。
- `total`：上面三个 true 的数量。

## 用户偏好

- 单词记忆方法优先考虑谐音，再通过谐音变成有趣的小故事。
- 中文谐音可以大胆一点，只要好记。
- 谐音必须自然，不要为了满足格式硬凑。
- 可以使用离谱、生活化、轻微吐槽式画面。
- 可以用中文、英文、罗马音混合联想；只要一眼能记住，就优先保留。
- 故事越具体越好：人物、动作、物品和结果要清楚。
- 多做家族串联：`今月/今週/今晩/今年`、`こちら/こっち/これ/この/こんな`、`三/四/七`。
- 易混词必须提醒：比如 `こっち/こちら`、`さき/さく`、`しち/なな`、`砂糖/塩`。
- 最终目的是复习时一眼能想起来，不追求文学感。
- 如果参考外部评论或词典，只能吸收思路，不能照抄长句。

## 输出给用户时

用户审核批次时，不输出完整 JSON。
